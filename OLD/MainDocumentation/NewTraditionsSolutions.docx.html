Se nos solicitó a New Traditions Solutions crear un sistema de seguimiento, control y supervisión de tierras agropecuarias, para esto vamos a dejar asentado como se maneja la empresa “Co Campo” hoy en día y cómo va a ser el sistema que va a adquirir a futuro.

Al día de hoy “Co Campo” cuenta con electrificación rural y se compone por la casa principal, casa de encargado y casa de personal, junto con un galpón y tinglado. Al inicio del día se reúne el encargo con los peones para aclarar cuales son las tareas a realizar. Entre ellas se encuentran tareas diarias (Dar de comer a los animales), tareas por períodos a corto y largo plazo (Cosecha y riego de los cultivos), tareas activadas por factores externos (Alambrado roto /Medidor de pluviómetro). Respecto a la facturación se lleva a cabo un sistema de facturación electrónica, la cual es respaldada con una posterior copia en papel con todos los datos, y respecto a los gastos se lleva a cabo un seguimiento rudimentario con papeles, notaciones y facturas de las compras. No tienen un sistema de momento, ni tampoco cuentan con un equipo para ello. Se lleva un registro en papel de las tareas relevantes realizadas en el día, vacunas, cambios en los grupos de animales, vacunas, etc. Tienen el plano de las hectáreas del campo detallado geográficamente.

Lo que se solicita por parte de “Co Campo” es lo siguiente:

  • Abarcar la exportación, inserción e importación de datos, para su posterior proceso estadístico.
  • La revisión y actualización de tales datos de una forma periódica.
  • Una visualización total de los rendimientos productivos.
  • Programación de tareas diarias y rutinarias.
  • Seguimiento histórico de ganado y cultivo.
  • Aplicación móvil.
  • Mapa interactivo y modificable.
  • Sistema de usuarios.
  • Sistema de facturación.
  • Seguimiento de costo.
  • Sistema de clima.
  • Sistema de tareas basado en prioridades.

MÓDULO: ABM TAREAS POR PRIORIDAD:
        Propósito:

  • Organiza tareas por orden de creación y/o prioridad dependiendo de la opción del usuario.
  • Modificar a gusto del usuario, y reorganizar prioritariamente el orden a su gusto.
  • Pueden ser eliminadas tras la petición del usuario y/o, tras la superación de tal fecha límite, reorganizando las demás tareas, con dicho orden de prioridad.

Caso de uso: 1. Dar de alta una nueva tarea.

El usuario ingresa una nueva tarea a realizar a futuro, con una fecha/hora de creación (provista por defecto, por el sistema) y una hora de finalización (por defecto 0).

Se espera que el sistema almacene tal texto, fecha-hora de creación (dato del ambiente) y fecha/hora de finalización (dato del usuario)


Si no se inserta un horario de finalización, tal tarea no vencerá, y aparecerá en primer orden dependiendo de la antigüedad de creación en comparación al resto.

Abreviaturas:

  • F/H fin: Fecha/hora finalización de la tarea a tratar, esto propone un vencimiento límite, y establece el orden de prioridad de forma automática, las tareas con F/H fin más cercanos a F/H actual tienen mayor prioridad.
  • G/H Inicio: Fecha/hora del inicio de la tarea, esto presenta la posibilidad de organizar por orden de llegada, por antigüedad, y poder llevar un control general de la base de datos.

ABM USUARIOS
Propósito:

  • Registro de nuevo usuario:
     Actor principal: Usuario
     El usuario podrá registrarse completando un formulario con sus datos personales. El sistema validará que no exista otro usuario con el mismo nombre y guardará la información en la base de datos.
  • Modificación de datos del perfil:
     Actor principal: Usuario
     Luego de iniciar sesión, el usuario podrá acceder a su perfil y editar sus datos personales.
  • Baja de usuario (lógica):
     Actor principal: Administrador
     El administrador podrá realizar una baja lógica del usuario. Esto implica que su acceso será deshabilitado, pero sus datos históricos se conservarán en el sistema.
  • Roles y permisos:
     Actor principal: Administrador
     Se podrán asignar roles a cada usuario (por ejemplo: administrador, empleado de campo, encargado), y cada uno tendrá distintos niveles de acceso y funcionalidades dentro del sistema.

LOGEO
Propósito:

  • Inicio de sesión:
     Actor principal: Administrador o Usuario
     El sistema permitirá iniciar sesión ingresando nombre de usuario y contraseña. Se validará que el usuario exista en la base de datos y que la contraseña coincida. Si los datos son correctos, el sistema permitirá el acceso.
  • Recuperación de contraseña:
     Actor principal: Usuario
     En caso de olvidar la contraseña, el usuario podrá solicitar su recuperación enviando un correo electrónico al administrador, quien le asignará manualmente una nueva contraseña.

CONTABILIDAD
Propósito:

  • Registro de ventas:
     Actor principal: Administrador
     Se podrán registrar ventas clasificándolas por forma de cobro (efectivo, transferencia, cheque) y por categoría (ganadería o cultivo). Los datos ingresados incluirán los detalles de la factura y se guardarán en la base de datos para su posterior análisis.
  • Registro de compras:
     Actor principal: Administrador
     Similar a las ventas, se podrán cargar compras detallando forma de pago y categoría del gasto. Los tickets o facturas también quedarán registrados para generar reportes y estadísticas. Se podrán añadir comentarios o notas adicionales por cada registro.
  • Estadísticas automáticas:
     Actor principal: Sistema
     El sistema procesa los datos de compras y ventas, generando resúmenes semanales y mensuales que reflejan el balance económico del establecimiento (gastos y ganancias).
  • Comentarios o notas:
     Actor principal: Administrador
     En cada registro de compra o venta, el sistema permitirá agregar un comentario libre o nota adicional para detallar observaciones relevantes. Estas notas quedarán guardadas junto con el registro y podrán ser visualizadas posteriormente como parte del historial contable.

MAPA
Propósito:

  • Edición de lotes:
     Actor principal: Usuario
     Se podrá editar en tiempo real la división de sectores (potreros, zonas de cultivo, etc.).
  • Asignación de colores por sector:
     Actor principal: Usuario
     El usuario podrá pintar cada sector con distintos colores, facilitando su diferenciación visual.
  • Distinción por tipo de uso:
     Actor principal: Usuario
     A cada sector se le podrá asignar una etiqueta para indicar si está destinado a ganado, cultivo, u otro uso.

ABM Animales

Propósito:

  • Permitir la gestión completa del ciclo de vida del ganado, desde el registro inicial hasta el seguimiento sanitario y nutricional, incluyendo baños, vacunas, pesajes, defunciones y dietas. Los animales se gestionan en grupos asignados a lotes/subdivisiones, con opciones para agregar/mover animales entre grupos y registrar eventos en batch por grupo cuando sea aplicable.
  • Registro de nueva caravana:

Actor principal: Usuario (encargado o administrador)

Se podrá dar de alta un nuevo animal completando un formulario con su número de caravana (único), peso, edad, tipo de alimento, historial sanitario (baños, vacunas), y ubicación en el lote. El sistema validará la unicidad del número de caravana antes de guardar los datos.

  • Registro de animales (alta):
    Actor principal: Usuario (encargado o administrador)
    Se podrá registrar un nuevo animal indicando número de caravana (único), tipo de ganado, sexo, fecha de nacimiento, peso inicial, comentario e imagen opcional. El animal debe asignarse a un grupo existente durante el registro. El sistema validará que no haya duplicados en el número de caravana.
  • Modificación de datos del animal:

Actor principal: Usuario (encargado o administrador)

El usuario podrá editar los datos del animal (peso, alimentación, estado sanitario, etc.) y agregar nuevas observaciones o registros diarios. También podrá actualizar la foto del animal.

  • Baja lógica de animal:

Actor principal: Usuario (encargado/peon o administrador)

Se podrá realizar una baja lógica del animal (por venta, fallecimiento, traslado), conservando los datos históricos en el sistema para futuras consultas.

  • Registro de dietas:
    Actor principal: Usuario (encargado o administrador)
    Las dietas se asignan por grupo (no por animal individual). Se selecciona un alimento existente (con marca y tipo asociado) y se registra la fecha automática. Se genera un historial de dietas por grupo, visible en los detalles de cada animal perteneciente al grupo.
  • Historial sanitario y seguimiento:

Actor principal: Usuario (encargado o administrador)

El sistema permitirá agregar y visualizar eventos sanitarios como vacunaciones, baños o tratamientos. Se podrá registrar un baño para todo un grupo de animales, indicando sólo la fecha (el sistema registra automáticamente la fecha actual). El sistema permitirá agregar vacunas aplicadas a animales individuales o en batch para un grupo, seleccionando el tipo de vacuna existente (con proveedor asociado) y registrando la fecha automática. No se registra precio en el evento, pero se hereda del catálogo de vacunas. Se podrán registrar pesajes periódicos para animales individuales o en batch para un grupo, indicando el peso en kg y registrando la fecha automática. Esto permitirá generar un historial médico completo por animal.

  • Registro de dieta:
    Actor principal: Usuario (encargado o administrador)
    Las dietas se asignan por grupo (no por animal individual). Se selecciona un alimento existente (con marca y tipo asociado) y se registra la fecha automática. Se genera un historial de dietas por grupo, visible en los detalles de cada animal perteneciente al grupo.
  • Registro de defunción:
    Actor principal: Usuario (encargado o administrador)
    En caso de muerte del animal, se podrá registrar la fecha automática y la razón detallada. Esto actúa como baja lógica, conservando el historial del animal.
  • Registro de datos de veterinario:
    Actor principal: Usuario (encargado o administrador)
    No se implementa un módulo específico para datos de veterinario. En su lugar, se pueden agregar recomendaciones o historial médico en los comentarios generales del animal, o en eventos sanitarios como vacunas/baños.

ABM Cultivos

Propósito:

  • Permitir la gestión completa del ciclo productivo de cultivos, registrando eventos clave como la siembra, sanidad, rendimiento y condiciones ambientales.
  • Registro de cultivo (alta):

Actor principal: Usuario (encargado o administrador)

Se podrá registrar un nuevo cultivo indicando lote o subdivisión geográfica, tipo de cultivo, fecha de siembra y cosecha, tipo de riego, fumigaciones realizadas y cantidad de semilla utilizada. El sistema validará que no haya superposición con otros cultivos ya asignados en el mismo lote y período.

  • Modificación de datos del cultivo:

Actor principal: Usuario (encargado o administrador)

Se podrán actualizar los datos del cultivo a lo largo del ciclo productivo, incluyendo correcciones de fechas, cambios en el tipo de riego, o modificaciones en el seguimiento sanitario.

  • Baja lógica del cultivo:

Actor principal: Usuario (encargado o administrador)

Al finalizar el ciclo productivo o en caso de pérdida de cultivo, se podrá dar de baja lógica conservando el historial de producción para análisis posteriores.

  • Registro sanitario y meteorológico:

Actor principal: Usuario (encargado o administrador)

Se podrán cargar eventos sanitarios (fumigaciones, control de malezas, etc.) y condiciones meteorológicas relevantes (lluvias, temperaturas extremas) para seguimiento del estado del cultivo.

  • Seguimiento de rendimiento:

Actor principal: Usuario (encargado o administrador)

El sistema permitirá registrar el rendimiento de cada cultivo por zona/lote, facilitando la comparación entre campañas y contribuyendo a la toma de decisiones futuras.

MÓDULO: CUADRO MENSUAL DE STOCK GANADERO

Propósito:
 Permitir al usuario cargar manualmente, de forma mensual, un cuadro similar a la planilla “Stock campo 1”, para llevar control del inventario de ganado por categoría, con registros de entradas, salidas y existencia final.

Datos a registrar (campos del cuadro):

  • Categoría de animales (Vacas >3 años, Vaquillonas, Terneros, Toros, etc.)
  • Existencia anterior / parición
  • Entradas
  • Traslado desde otros campos
  • Compras
  • Salidas
  • Ventas
  • Traslados a otros campos
  • Consumo / Mortandad
  • Existencia a fin de mes
  • Totales Generales
  • Observaciones

Funcionalidades principales:

  1. Alta manual de cuadro mensual (selección de mes y año).
  2. Carga manual de datos en tabla estructurada por categoría.

-- ALTERNATIVO - Stored Procedure

DELIMITER //

CREATE PROCEDURE `sp_crear_usuario`(

    IN  p_nombre            VARCHAR(100),

    IN  p_apellido          VARCHAR(100),

    IN  p_mail              VARCHAR(150),

    IN  p_password_hashed   VARCHAR(255),

    IN  p_id_categoria_rol  INT

)

BEGIN

  DECLARE v_cnt INT DEFAULT 0;

  -- 1) Verificar unicidad (Comprueba que no esté repetido dato Mail)

  SELECT COUNT(*) INTO v_cnt

    FROM `Usuarios`

   WHERE `mail` = p_mail;

 

  IF v_cnt > 0 THEN

    -- Ya existe: devolvemos código y mensaje

    SELECT

      1  AS error_code,

      'ERROR: El correo ya está registrado.' AS message;

  ELSE

    -- 2) Insertar nuevo usuario (Tras validación, ALTA de usuario)

    INSERT INTO `Usuarios`

      (`nombre`,`apellido`,`mail`,`contraseña`,

       `estado`,`fecha_estado`,`id_categoria_rol`)

    VALUES

      (p_nombre, p_apellido, p_mail, p_password_hashed,

       'espera', NOW(), p_id_categoria_rol);

    -- 3) Respuesta de éxito

    SELECT

      0 AS error_code,

      'Email enviado al administrador. Espere aprobación.' AS message;

  END IF;

END//

DELIMITER ;
